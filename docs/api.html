Reference

API reference

Nine functions and one error class. Every one takes the locale as an argument, so data from Berlin, Mumbai and Cairo can sit side by side.

7 min readUpdated October 15, 2026numberparrot 1.0.0

All functions take an optional locale: a BCP 47 tag ("pt-BR"), a list of tags, or nothing for the runtime default. Locale data is read from Intl.NumberFormat#formatToParts() once and cached. Pick a locale in the panel next to this page to see what it uses.

parse#

parse(input, locale?, options?): number

Returns a number, or NaN when input is not a valid number for the locale. Numbers are returned unchanged. The locale is a BCP 47 tag ("pt-BR"), a list of tags, or nothing for the runtime default.

OptionTypeDefaultDescription
strictbooleanfalseThrow NumberParseError instead of returning NaN. Only the exact separators of the locale and recognized currencies are accepted, and a decimal separator needs digits on both sides.
keepPercentbooleanfalseReturn 15 for "15%" instead of 0.15.
looseGroupingbooleanfalseAccept group separators anywhere ("1,23,4"). By default they must sit where thousands, or Indian lakh and crore, groups go.

Besides the locale's own format, the default lenient mode accepts any whitespace (including U+00A0 and U+202F) or apostrophe as a group separator, the other one of . and , as a group separator, a leading (.5) or trailing (5.) decimal separator, signs and currency on either side, exponents (E, e, ×10^), ∞, and digits in any script.

tryParse#

tryParse(input, locale?, options?): ParseResult

Takes the same arguments and options as parse and returns { ok, value, code, message }. When ok is false, value is NaN and code and message are the ones NumberParseError would carry, so a form can show a precise message without strict mode or try.

parseCurrency#

parseCurrency(input, locale?, options?): CurrencyResult

Returns { amount, currency, symbol, fractionDigits }:

  • amount: the number, or integer minor units with toMinorUnits. NaN when invalid.
  • currency: the ISO 4217 code, or null when none was found or recognized.
  • symbol: the currency text as written (normalized), or null.
  • fractionDigits: minor unit digits of the currency (2 for USD, 0 for JPY, 3 for BHD), or null.
OptionTypeDefaultDescription
toMinorUnitsbooleanfalseReturn an integer of minor units, computed on the decimal digits as text.
currencystringnoneISO code to assume when none is written. In strict mode a different currency throws CURRENCY_MISMATCH.
strictbooleanfalseAs in parse; unknown currencies throw UNKNOWN_CURRENCY and rounding throws PRECISION_LOSS.
looseGroupingbooleanfalseAs in parse.

Symbols are resolved through Intl for the locale, so the same $ means USD in en-US, CAD in en-CA and MXN in es-MX.

detect#

detect(input, candidates?): DetectResult

Guesses how a number string was written. candidates defaults to DEFAULT_CANDIDATES (23 common locales, en-US first); their order breaks ties.

FieldTypeDescription
valuenumberBest guess, NaN when the string is not a number in any convention.
decimalstring | nullDecimal separator found or assumed.
groupstring | nullGroup separator found or assumed.
ambiguousbooleanTrue when the string means two different numbers depending on the locale.
confidencenumber0 to 1. 1 means only one reading is possible, 0.5 means a coin flip.
reasonstringShort English explanation.
localesstring[]Candidates that read the string as value, best match first.
alternativesnumber[]Every distinct reading, value first.

Switch the world board on the home page to Detect mode to see every reading of a string across 39 locales.

parseColumn#

parseColumn(values, candidates?): ColumnResult

A single "1,234" is ambiguous, but a column rarely is. parseColumn runs detect on every cell, lets the unambiguous cells vote for the decimal separator, picks the first candidate locale that writes it and reads every cell with that one locale. candidates works as in detect.

FieldTypeDescription
valuesnumber[]One number per cell. Blank cells and cells that do not fit are NaN.
localestring | nullThe candidate used for every cell, null when no cell is a number.
decimalstring | nullThe decimal separator chosen for the column.
ambiguousbooleanTrue when no cell settles the format and the candidate order decided.
confidencenumber0 to 1. Lower when cells disagree or do not fit.
reasonstringShort English explanation naming the deciding cell.
invalidnumber[]Indexes of non blank cells that are not numbers in the chosen format.

Paste a column into the box at the top of the home page to try it.

isValid#

isValid(input, locale?, options?): boolean

true when parse would return a number. Never throws, even with strict: true.

createParser#

createParser(locale?, options?): Parser

Resolves the locale once and returns { info, parse, tryParse, isValid, parseCurrency, normalizeInput } bound to it. The fastest way to parse many values, for example every row of a CSV file.

normalizeInput#

normalizeInput(value, locale?, options?): InputState

Returns { text, value, valid, complete } for a form field. text is the cleaned field text and complete is false while the user is still typing, for example right after a decimal separator. Options: maxFractionDigits (drop extra fraction digits) and allowNegative (default true).

getLocaleInfo#

getLocaleInfo(locale?): LocaleInfo

Returns { locale, numberingSystem, decimal, group, minusSign, plusSign, percentSign, exponent, digits }, read from Intl.NumberFormat#formatToParts() once and cached. The locale picker on every docs page is built on it.

NumberParseError#

class NumberParseError extends Error

Thrown in strict mode. Has code, input and locale.

CodeMeaning
EMPTYThe input is empty or only whitespace.
NOT_A_STRINGThe input is not a string or a number.
NO_DIGITSThe input contains no digits.
INVALID_CHARACTERAn unexpected character appears inside the number.
INVALID_SEPARATORA separator is not valid for the locale (strict mode) or appears twice in a row.
MULTIPLE_DECIMALSMore than one decimal separator.
MIXED_GROUPSTwo different group separators in one number.
INVALID_GROUPINGGroup separators in the wrong place, like 1,23 in en-US.
INVALID_SIGNDuplicated or conflicting signs or parentheses.
INVALID_AFFIXText before or after the number that is not a sign, percent or currency.
UNKNOWN_CURRENCYStrict mode found a currency it cannot identify.
CURRENCY_MISMATCHThe written currency differs from the currency option.
PRECISION_LOSSConverting to minor units would need rounding (strict mode).
OUT_OF_RANGEThe value is not finite, or not a safe integer where one is required.

Runtime support#

  • Node.js 18 and newer, Deno, Bun and all modern browsers. Requires Intl.NumberFormat with formatToParts and full ICU locale data, which Node ships by default since version 13.
  • The whole library is about 7 kB gzipped. Importing only parse costs about 3.6 kB.
  • ESM (dist/index.js), CommonJS (dist/index.cjs) and type definitions for both.
